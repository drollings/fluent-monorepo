# protopyne-rs — Architecture Map & Capability Index

_Read this first, then drill into the cited `path :: Symbol` markers. Explanatory
text is intentionally terse: expand it by reading the code at the markers._

## 0. Handoff for new agents

Entry point for the eight `protopyne-*` crates, indexed by capability with exact
`path :: Symbol` references so you can jump straight to the relevant file.
Drill into the cited symbols rather than re-exploring. Counts (when cited) follow
one rule — every `*.rs` under `src/protopyne-*/src/` and `src/protopyne-*/tests/`
(kernels `tests/common/fixture.rs` included); the paint-edge crates
(`fluent-egui`, `protopyne-egui`) are counted separately. If you add or remove a
file, update the count on the same row — a stale count is a broken entry point.

Companion docs in `doc/protopyne-rs/`:

- `README.md` — operations: what the project does, build/run/test, CLI, container.
- `VISION.md` — economics, safety invariants, platform direction (aspirational).
- `INJECTION_CONTRACT.md` — headless MTF/tick injection contract for the Pine
  harness (per-`request.*`-arm live-vs-injected, tick/confirm accounting, fixture
  map, harness bounds).
- `RUNBOOKS.md` — operator runbooks (halted-book recovery, alert files,
  cert-sandbox soak).

**Direction of record:** Rust-only — no browser/JavaScript/Node.js anywhere.
`egui` (required) / `eframe` (optional `demo` shell) are confined to the two
paint-edge crates: `src/fluent-egui` (display scaffolding; blind to
indicator/regime/trading logic, but coupled to the chart display types
`protopyne-chart-model`/`protopyne-chart-scale`/`protopyne-types`) and
`src/protopyne-egui` (trading terminal over it). `egui-charts` is reference only,
never a dependency.

**Conventions (from `AGENTS.md`):** unit tests live in `src/<crate>/tests/<module>.rs`
with a `#[path]` forwarder in the source module, never inline `mod tests`; shared
crates under `src/` must not import from `guidance`/`router`/`coral`/`wasm_ipc`;
never write planning identifiers into code or comments; hermetic tests stay on
loopback. Skill docs govern implementation: `doc/skills/{common-core,fluent-wvr,fluent-concurrency,dag,db}/SKILL.md`.

## 1. Overview

- **Languages:** Rust only (edition 2021/2024 per workspace). No interpreter in
  the runtime path (the container build fails if one appears); no browser/JS/Node
  in build, test, or run — chart data leaves the server as JSON rows for a native
  terminal, never a web chart library.
- **Build:** Cargo workspace (`Cargo.toml`, resolver v3). Eight trading/chart
  member crates plus paint-edge `src/fluent-egui` (scaffolding) and
  `src/protopyne-egui` (terminal); shared libs (`common-core`, `fluent-wvr`,
  `fluent-concurrency`, `fluent-dag`, `fluent-db`) and third-party crates come
  from the workspace `[dependencies]`. `egui`/`eframe` are dependencies of the
  two paint-edge crates only, enforced by `tests/lib.rs` + `tests/budget.rs` in
  each (the headless scan exempts `src/protopyne-egui` as the second paint edge).
- **Layout:** `src/protopyne-{types,kernels,strategy,venue,server,chart-model,chart-scale,view,store}/`
  and `src/fluent-egui/`, `src/protopyne-egui/` — each `src/*.rs`, `tests/*.rs`,
  `Cargo.toml` (`autotests = false`, explicit targets via `#[path]` forwarders).
- **Entry points:** library roots (`src/protopyne-*/src/lib.rs`, all
  `#![forbid(unsafe_code)]`; chart crates are library-only). One binary
  (`src/protopyne-server/src/main.rs :: main`, HTTP server, default bind
  `127.0.0.1:9060`); one container (`src/protopyne-server/Containerfile` + its
  `smoke-container.sh`). Make targets (`Makefile`): `protopyne`,
  `protopyne-start`/`-stop`, `protopyne-test`, `protopyne-trading-suite`,
  `protopyne-container-smoke`, `protopyne-demo` (interactive terminal) plus
  `protopyne-demo-chart` and `protopyne-demo-check` (headless contract, byte-pinned
  goldens in `src/protopyne-egui/tests/data/`). `make protopyne-test` gates the
  six trading crates; the two chart crates are covered by the workspace build.
- **Test data:** trimmed fixtures + goldens under each crate's `tests/data/`
  (kernels: SPY trims, `sma14.json`/`ema14.json`/`parity_sma10.csv`,
  `tests/data/golden/`, the tick-harness windows + `tick_harness_baselines.json`;
  server: ingest goldens + `pine_integration_lite_*`/`pine_task_*` proof
  goldens). The Pine closure fixtures read real indicator sources from
  `data/protopyne-rs/` (`historical/`, `indicators/`, `libraries/`).
- **Runtime model:** synchronous decision core (pure functions over values) plus a
  Tokio perimeter: one axum server task, `Scope`-owned feed/session tasks,
  `ResultPool` sweep workers, broadcast fan-out. No global singletons in the
  trading path; per-run contexts (`RunCtx`, `GrantUsage`) and per-session scoped
  indexes (`SymbolIndex`) keep parallel runs isolated. Sessions bind a
  `VenueRegistry` routing table, not a single paper venue; single-venue callers
  pass `VenueRegistry::single` and behave identically.
- **Architecture summary:** layered pipeline `types → kernels → strategy → venue
  → server`, with `chart-model`/`chart-scale` as `egui`-free paint-edge leaves off
  `types` (bars) and `server` (chart rows); display `f64` appears only at the
  `to_display_float` boundary and never flows back into decisions. Each layer owns
  its vocabulary and validates fail-closed through the shared `Validate` trait
  (C34). The single decision path is `Signal → RiskEngine → evaluate_grant →
  Venue::submit`, executed identically by backtest replay (multi-symbol, C45),
  paper sessions, and HTTP preview, with byte-identical manifests
  (`to_canonical_json` rerun equality) proving it. Operator control
  (halt/resume/close-all/cancel-all) enters as journaled rows through the command
  plane (C40), never as out-of-band mutation.

## 8. Notable Features Worth Reimplementing

- **C9 + C15 (risk token demanded by submission):** typestate makes the safety property unrepresentable to violate — the cheapest "cannot bypass" guarantee for any gated pipeline.
- **C14 (intent-before-venue + outbox + replay):** kill-mid-submit from three primitives (durable intent, idempotent IDs, query-by-ID) with no distributed machinery.
- **C10 (tighten-only arming with worst-case preview):** monotonic authorization plus showing exposure before confirmation — portable to any approval workflow.
- **C21/C22 (shared decide path + byte-identical manifest):** one function for backtest and paper plus canonical-JSON rerun equality turns "what you test is what you trade" into a test.
- **C24 (refuse-don't-miscompile spike):** accept and reject rates both gated at 1.0 *before* output may be cached — a discipline for any partial-coverage transpiler.
- **C26/C27 (headless chart leaves):** `Decimal`-native bars in, plain-data rows out, `egui`-free by construction — the display boundary as a pure function, so the paint edge can never smuggle authority back into decisions.
- **C34 (shared `Validate` + execute bridges):** one trait shape for every config surface with per-type errors preserved, and one bridge into supervision — the pattern for adding a validator without a new idiom.
- **C39 (registry routing without an enum):** `Arc<dyn Venue>` + ordered fallback + query-first idempotency — how to add a venue without touching `safe_submit` or any call site.
- **C40 (journal-first commands):** halt/resume/close-all/cancel-all as journaled rows with last-wins replay — operator control that survives a kill-mid-command.
- **C32/C41/C16 (chain → spread fills → OCC reconciliation):** defined-risk validation at construction, atomic per-leg fills, per-OCC leg-net compare — the options-spread safety loop in three layers.
- **C44 (portfolio aggregation + tearsheet):** one `aggregate` over booked fills feeding both JSON report fields and a text tearsheet from the same structs — no second summarizer to drift.
- **C46–C49 (Pine engine + checked parity matrix):** a full language runtime whose overlap contract with the reference layer is machine-checked (207 rows of identical/pinned/refused, each refusal with an executable probe), so partial coverage cannot silently miscompute; whole-library native serving rides alongside (not through) the engine, frozen by the SPY agreement goldens.
- **C50–C52 (shared clock + durable ring + quiet labels):** one ET wall-clock read by kernels and chart sessions (C50); stored opens + signed-remainder trims + generation-keyed incremental MTF with content-hash backdating (C51); hysteresis-wrapped regime reads leaving the frozen detector untouched for parity (C52).
